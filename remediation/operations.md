# I/J/N/S/T — configuration and controlled rollout

No deployment or push is performed. Preserve all existing B/C storage, backup and demo configuration.

- Set `APP_URL` to the canonical origin (no path/trailing slash), and optional comma-separated `CORS_ALLOWED_ORIGINS` for additional trusted browser origins. Production never adds localhost implicitly. Requests without Origin remain allowed for server-to-server clients.
- Set `CSP_STORAGE_ORIGINS` to exact browser-facing object storage origins. CSP begins in report-only mode because live asset/storage origins have not been observed. Review browser violations through upload/download, fonts, voice and OAuth flows, then explicitly set `CSP_ENFORCE=true`. HSTS requires the production HTTPS reverse proxy. Frame and MIME protections are enforced immediately. Existing Google Fonts origins are specifically allowed.
- Reconnect Microsoft mailboxes to replace subscriptions created with mismatched clientState. Preserve encrypted tokens; no database values are rewritten here. Both OAuth and renewal now send the exact persisted state. Webhook matching requires connected Microsoft subscription ID plus state; malformed/unknown notifications are skipped. Validate the provider's validationToken handshake, mixed batches and reconnect/disconnect in staging.
- Normalized ingestion remains behind a staff session and `EMAIL_INGESTION_ENABLED=true`. Configure `EMAIL_PROVIDER_NAME` and a separate random `EMAIL_INGESTION_SECRET` (at least 32 characters); the trusted adapter sends it in `X-Email-Ingestion-Token`. This secret belongs only to the verified provider adapter, never the browser. The adapter must authenticate the upstream source. Ingestion rejects arbitrary fields/matter IDs and mismatched providers. Rotate adapter/server values together. Automatic matter matching is retained for authenticated trusted mail.
- Set a separate random `METRICS_TOKEN` of at least 32 characters. Mount the same value as the Prometheus credentials file. Restrict `/api/metrics` at the reverse proxy/network to the monitoring network; the endpoint additionally requires bearer authorization and otherwise returns 404. Adjust the example target/port to the actual Compose service. No PII is included in labels.
- Metrics expose request counts/latencies/status by fixed category, including rejected matter creation (matters/409), storage errors, AI/provider errors and auth failures. `apz_research_provider_failures_total` also counts failed research AI calls even when the response successfully returns internal results. Wire supplied alert rules into the host's existing Alertmanager/Grafana and validate with `promtool check config`/`check rules` before reload.

CI runs frozen install, unit tests, typecheck, builds and production dependency audit; it has read-only repository permissions and no deployment credentials or automatic deploy step. Fix any documented pre-existing typecheck failure before treating CI as release approval.

Rollout: review diff and passing verification; restore a staging backup using the completed Section C process; run reviewed migrations in the documented order; exercise the remediation manual QA; build/version the image; obtain release approval; deploy through the existing Compose procedure; check health, storage and metrics; retain the prior image and configuration. Rollback uses the prior image with compatible schema and retained secrets; do not reset invoice sequences or restore over a live database automatically. All host configuration remains manual.
