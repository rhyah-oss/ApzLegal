# APZ LEGAL — BUILD FIRM PRODUCTIVITY DASHBOARD FROM EXISTING TIME TRACKER

## OBJECTIVE

Build a new **Firm Productivity** dashboard within APZ Legal.

The Firm Productivity dashboard must use the **EXISTING TIME TRACKER as its single source of truth**.

DO NOT create a second time-tracking system.

DO NOT create duplicate time-entry functionality.

DO NOT introduce billing, invoicing, revenue, fees, billable hours, or financial reporting.

This is purely a **productivity, activity, workload and time-analysis dashboard**.

The purpose is to transform the raw time entries already captured by the Time Tracker into a clear management dashboard showing:

* Where the firm's time is being spent
* What activities are consuming the most time
* Which matters are consuming the most time
* How work is distributed across employees/teams
* How activity changes over time
* Workload patterns
* Productivity trends
* Time-tracking quality
* Data-driven productivity insights

---

Before making changes, inspect the existing Time Tracker implementation completely.

Identify:

* Database tables/models
* Time-entry schema
* API endpoints
* Frontend components
* Time-entry creation
* Start/stop timer functionality
* Manual time entry
* Matter association
* User association
* Activity types
* Descriptions
* Start/end timestamps
* Duration calculations
* Statuses
* Categories
* Tags
* Existing reports
* Existing filters
* Existing permissions

DO NOT replace the existing Time Tracker.

DO NOT alter its core functionality unless necessary.

The Firm Productivity dashboard must consume the existing Time Tracker data.

---

# 2. DEFINE THE DATA FLOW

The architecture should be:

TIME TRACKER
↓
TIME ENTRIES
↓
PRODUCTIVITY ANALYTICS
↓
FIRM PRODUCTIVITY DASHBOARD

The dashboard must aggregate existing time entries.

For example:

If the Time Tracker contains:

User A
Matter ABC
Legal Research
09:00–10:30
1.5 hours

The dashboard should automatically calculate:

* +1.5 total hours
* +1 research activity
* +1 matter worked on
* +1 activity for User A
* +1.5 hours for the relevant practice area/team

There must be NO second data-entry process.

# 6. EXECUTIVE KPI SUMMARY

At the top of the page create clean KPI cards.

Include:

### Total Time

Total hours recorded during the selected period.

### Activities Logged

Total number of time/activity entries.

### Active Users

Number of users who recorded time during the selected period.

### Active Matters

Number of unique matters with recorded activity.

### Average Hours / User

Total recorded hours divided by active users.

### Average Hours / Day

Average recorded hours across the selected working days.

### Tasks Worked On

Where time entries are linked to tasks, show the number of tasks worked on.

### Tasks Completed

Where task completion data exists, show completed tasks during the period.

IMPORTANT:

These figures must be calculated from REAL application data.

DO NOT use hardcoded numbers.

DO NOT use mock data.

**214h Legal Research**

↓

**Time Tracker**

with:

Activity Type = Legal Research

Date = Selected Period

Then display the actual entries.

Similarly:

Click:

**Matter A — 84 hours**

↓

Open/filter the Time Tracker for:

Matter A

Click:

**Employee A — 168 hours**

↓

Open/filter the Time Tracker for:

Employee A

The user must always be able to understand where dashboard numbers came from.
