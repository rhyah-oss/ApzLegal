## 1. PURPOSE OF THE TEMPLATES MODULE

Templates must function as a **controlled legal template library**, not simply a file upload/download page.

The intended lifecycle is:

**Create/Upload → Categorise → Review → Approve → AI Index → Available to Legal Staff → Create Matter Document → Version/Track/Audit**

The User Journey specifically requires that a Partner/Senior Partner can upload:

* Templates
* Legal opinions
* Internal guidance

and categorise the content, mark it as Approved, trigger AI indexing, and make the approved content available to legal staff.

For this implementation, focus specifically on the **Templates** portion of that workflow.

# 3. TEMPLATE STATUS MODEL

Implement a proper lifecycle.

Use:

**Draft**

→ **Pending Review**

→ **Approved**

→ **Archived**

Also support:

**Changes Required / Rejected**

Rules:

### Draft

Template is being prepared and is not available to general legal staff.

### Pending Review

Template has been submitted for Partner review.

### Approved

Template is officially approved for firm use.

An approved template can:

* Be used to create matter documents
* Be indexed by AI
* Be retrieved by the Legal AI/Knowledge Base
* Be available to authorised legal staff

### Archived

Template is retained for historical/audit purposes but should no longer be selectable as the current template.

Do NOT delete historical versions when a template is archived.

# 9. VERSION CONTROL

Templates must support versioning.

Never overwrite the historical approved version.

Example:

```text
Letter of Demand

v1.0 — Archived
v2.0 — Archived
v3.0 — Approved / Current
```

When a new version is created:

* Preserve the previous version
* Increment the version
* Keep historical metadata
* Maintain the audit trail
* Require approval for the new version

Only the current approved version should be treated as the firm's active template.

# 10. CREATE DOCUMENT FROM TEMPLATE

This is one of the most important functions.

An authorised legal user should be able to select:

**Create Document**

from an approved template.

The system should then:

### Step 1

Ask the user to select a Matter.

### Step 2

Create a new document based on the approved template.

### Step 3

Associate the new document with the selected matter.

### Step 4

Store the document inside the Matter Workspace.

The created document should then enter the normal APZ Legal document lifecycle:

**Draft → AI Assist → Review → Partner Approval → Client Signing → Archived**

where applicable.

Do NOT create a completely separate document workflow for templates.

Use the existing Document Management workflow.
